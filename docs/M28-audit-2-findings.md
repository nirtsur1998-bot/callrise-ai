### V5 · HIGH · FIELD-CRITICAL — Headings and lists render as literal markdown unless preceded by a blank line
- **Where:** `src/renderer/src/features/assistant/markdown-blocks.ts:66` (area A-markdown-streaming)
- **Claim:** parseBlock classifies a chunk all-or-nothing — a heading only counts if it is the ONLY line in the chunk (`heading && lines.length === 1`, :66) and a list only counts if EVERY line matches the marker regex (`lines.every(...)`, :69/:72/:75) — so any list or heading that a model emits without a blank line separator falls through to the paragraph branch at :78 and the user sees raw `##` and `-` characters, permanently, not just while streaming.
- **Failure:** I ran the real parser on a realistic Rise reply: "Here's your day:\n\n## 10:00 — Dana Reyes\nRenewal call. She asked about the annual plan [1].\n\n**Next steps:**\n- Send the annual pricing sheet\n- Confirm the security review date". With final=true it produces exactly TWO paragraph blocks. The user sees the literal text `## 10:00 — Dana Reyes` (hashes visible, no heading style) and `- Send the annual pricing sheet` / `- Confirm the security review date` as plain lines separated by <br> (AssistantView.tsx:316-326), with no bullets and no indentation. Same failure for an ordered list whose item wraps onto a continuation line (`1. Call Dana back…\n   she asked about…\n2. Send Ben the deck` -> one paragraph with literal `1.` and `2.`). Separately, the heading regex at :65 is `#{1,3}` only, so `#### Four hashes` also renders as literal text. A bold lead-in immediately followed by a list (`**Next steps:**` then `- item`) is among the most common shapes an LLM emits, so a large fraction of Rise answers will show raw markdown.
- **Verifier:** Verified by running the REAL module (tsx importing src/renderer/src/features/assistant/markdown-blocks.ts). No guard, caller, or test prevents it.

Mechanism, each line read:

- markdown-blocks.ts:66 `heading && lines.length === 1` — a heading with body text under it is not a heading.
- markdown-blocks.ts:69/:72/:75 `lines.every(...)` — one non-matching line (a bold lead-in, a wrapped continuation) disqualifies the whole list/quote.
- markdown-blocks.ts:65 `#{1,3}` — #### and deeper never classify.
- markdown-blocks.ts:78 — everything falls through to paragraph.
- AssistantView.tsx:316-326 — paragraph branch emits lines joined by <br/> through InlineRun; InlineRun (AssistantView.tsx:250-252) passes non-bold/italic/code text straight into <span>{seg.text}</span>, so `##` and `- ` are printed verbatim. tokenizeInline (markdown-blocks.ts:91-111) has no block-marker handling.

- No normalization in transport: assistant-ipc.ts:313 `turn.accumulated += chunk.delta` and :379 `text: reply` are verbatim; the only .trim() in useAssistantChat.ts (:200) is on the USER's input, not the reply.
